# Obsidian 0.0.2 - Phase 0

This patch fixes the first real Windows 11 runtime test of Phase 0.

## What changed

- Minecraft 26.2 currently defaults to OpenGL. Obsidian 0.0.1 treated that as fatal and crashed before the player could reach Video Settings.
- Obsidian 0.0.2 now treats non-Vulkan startup as a safe inactive state. It logs the active backend and tells the player to select **Video Settings > Graphics API > Prefer Vulkan (Experimental)**, then restart.
- The Obsidian renderer bridge is only marked ready after Vulkan is actually active.
- The obsolete `failOnNonVulkan` configuration property is no longer used, so old Phase 0 config files cannot preserve the startup crash.
- Release automation now derives tag and artifact names from `mod_version` instead of hardcoding the original Phase 0 version.

## Validation status

The original 0.0.1 runtime test confirmed that Fabric loaded Obsidian successfully on Windows 11 with Java 25 and detected the reference AMD Radeon RX 6800 XT. The observed failure was specifically the intentional OpenGL backend rejection, not a Fabric/Java/GPU initialization failure.

0.0.2 still requires a follow-up runtime test with Minecraft set to **Prefer Vulkan (Experimental)** before Phase 0 can be considered Vulkan-runtime validated.

## Scope

Phase 0 still does not replace terrain rendering or provide a performance improvement. It establishes the Vulkan/backend lifecycle boundary that Phase 1 will build on.
