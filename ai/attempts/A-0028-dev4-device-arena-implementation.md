# A-0028 - Implement Phase 1 dev4 device geometry arena/suballocator

**Date:** 2026-08-20  
**Objective:** Build the first reusable device-preferred GPU geometry arena on top of dev3's validated staging path, with bounded allocation, stable generation-safe handles, completion-gated frees/reuse, fragmentation metrics, and a deterministic non-visual runtime probe.  
**Action:** Added `DeviceGeometryArena` backed by one 512 KiB validation `GpuBuffer` using `COPY_DST | COPY_SRC | VERTEX | INDEX` and no mapping flags. Added 4096 preallocated allocation slots, packed `(slot,generation)` 64-bit handles, sorted/coalescing free spans, best-fit aligned allocation, bounded allocation failure, fixed retirement-batch metadata, zero-timeout fence polling, and arena metrics. Added `DeviceArenaProbe` with sequence `allocate A/B/C -> intentionally fail full-capacity allocation -> batch-upload A/B/C -> read back B while retiring it behind the readback fence -> allocate D into B's freed span -> verify same slot/offset with advanced generation -> deliberately reject stale B handle -> upload D -> read back A/C/D while retiring all three -> verify data -> require one full coalesced free span`. Extended `StagingUploadArena` to accept destination slices. Wired the arena/probe into `FrameCoordinator`, removed the completed dev3 probe, bumped version to `0.1.0-phase1-dev4`, and removed the temporary backend inspection workflow.  
**Result:** `SUCCESS` at compile/CI stage; real-machine runtime validation pending.  
**Intended effect:** Prove that future chunk geometry can live in a bounded reusable GPU buffer without per-mesh GPU-buffer allocation, unsafe offset reuse, frame-count lifetime guesses, or fallback growth.  
**Actual effect:** GitHub Actions run `32368901978` passed on Java 25 / Gradle 9.5.1 after the dev4 implementation and an additional performance cleanup. During review, a temporary `int[]` allocation inside `retireBatch` was found and removed; retirement validation/state transition is now allocation-free in steady state.  
**Evidence:** Branch `phase1/device-arena`, draft PR #6, GitHub Actions build run `32368901978`, implementation files `render/memory/DeviceGeometryArena.java` and `DeviceArenaProbe.java`.  
**Why it worked:** The implementation stays within the already-proven Minecraft-owned Vulkan device boundary and reuses the validated staging/fence primitives instead of introducing a second memory/upload subsystem. Fixed metadata arrays make capacity and failure behavior explicit.  
**Side effects / lessons:** Best-fit free-span search is intentionally simple and bounded for this foundation; it is not yet claimed to be the final high-scale allocator algorithm. Profiling under real terrain churn should decide whether bins/TLSF/buddy-style metadata is warranted. Runtime must still prove that reuse/coalescing/generation safety behave as intended on the RX 6800 XT.  
**Next action:** Run final exact-head CI after documentation updates, distribute the CI-built dev4 JAR, and validate the full allocate/upload/retire/reuse/readback/coalesce sequence on the reference Vulkan machine before merging PR #6.
